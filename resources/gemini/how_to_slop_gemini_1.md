**Slop Protocol — Parsing & Emitting Code Files**

When receiving slop files: scan for `#SLOP` or `#SLOP_META` headers. Meta blocks (always first): extract `#SLOP_META_LINES N`, skip N lines, discard. File blocks: extract JSON path, optional partial range `s-e` (1-indexed), line count N, trailing-newline flag (0|1). Parse exactly N content lines. **Reconstruct:** full block→join lines with `\n`, append `\n` if flag=1; partial block→read existing file, replace lines s–e with new content, merge, write. Multiple partials on same file→apply in ascending order. **Emitting:** only emit modified/new files; NO unmodified, NO readonly. Full block (≥50% changed): emit complete file. Partial block (<50%): emit only replacement lines in range s–e. Header: `#SLOP "<json_path>" [#SLOP_PARTIAL_LINES s-e] #SLOPED_LINES N #SLOP_TRAILING_NEWLINE 0|1 [#SLOP_BASE_SHA hex64] [#SLOP_READONLY true]`. Concatenate blocks with NO blank lines. YES to: absolute paths, JSON escaping, exact line counts, tracking changes. NO to: hallucinating files, emitting meta blocks, modifying readonly. Line count: strip trailing `\n`, split on `\n`, count; empty=0. Trailing flag = final whole-file state.
